# アプリ仕様書：リハウス

## 1. アプリの名前と目的
* **アプリ名**: リハウス
* **目的**: 
  * **ターゲット**: 外食費の高騰に困っている学生や観光客
  * **解決策**: 地域課題である「増え続ける空き家」を活用し、安価で長居できるセルフキッチンスペースおよび関連サービス（商品購入等）を提供する。

---

## 2. 画面一覧（画面名と表示内容）

| 画面名 | 表示内容 |
| :--- | :--- |
| ホーム画面 | 各機能への導線ボタン（「予約する」「購入する」「マイページ」「新規ログイン」）、店舗基本情報（営業時間・場所）、お得なお知らせバナーを表示 |
| 登録・ログイン選択 | 「新規登録」および「ログイン」を選択する初期画面 |
| アカウント作成 | アカウント作成用のフォーム（メールアドレス・パスワードの入力）を表示 |
| プロフィール登録 | ユーザープロフィール情報（プロフィール画像、ユーザーネーム、電話番号）の入力フォームを表示 |
| 予約・日付選択 | カレンダーから希望利用日を選択する画面（混雑状況アイコン付き） |
| 予約・プラン選択 | セットプラン（キッチン2時間利用＋セットプラン等）を利用するかしないかを選択する画面 |
| 予約・時間選択 | 利用時間（1時間〜5時間）を選択する画面 |
| 予約確認 | 選択した予約日・予約時間・セット内容の最終確認および確定を行う画面 |
| 商品選択 | 販売中の商品（カップラーメン、飲み物、お菓子等）の一覧と商品詳細・購入数の選択画面 |
| カート画面 | カートに入れた商品の確認・数量調整画面 |
| 購入画面（決済・完了） | 注文内容一覧・お支払い金額の最終確認および「お支払いをする」ボタン、完了案内を表示 |
| マイページ | ユーザー情報（名前・利用回数）、スタンプカード機能、予約・購入履歴、アカウント設定へのリンクを表示 |
| アカウント設定 | アカウント登録情報の確認・変更画面 |

## 7. 守る条件

1. **技術スタック制限**:
   * HTML5、CSS3、JavaScript (Vanilla JS) のみを使用する。
   * データベースおよびサーバーサイド処理（ログイン認証含む）は実装しない。
2. **ファイル構成**:
   * CSSは `./style.css` の1ファイルに集約し、全画面で共通読み込みを行う。
   * JavaScriptは `./script.js` の1ファイルに集約し、全画面で共通読み込みを行う。
   * リンク・リソースパスはすべて `./` から始める相対パスを使用する。
3. **デザイン・レスポンシブ**:
   * スマートフォン端末（375px〜430px程度の幅）での閲覧に最適化する。
   * カラーパレットは白・黒・灰色（モノトーン）を基本とし、ワイヤーフレームの見た目を踏襲する。
4. **表記・文字**:
   * ワイヤーフレーム内のカッコ `（ ）` は仮の記号であるため画面表示からは除外し、中身の文字（例：「確定する」）をそのままボタンテキストとする。
   * 実在の人物・店舗・地名・連絡先は使用せず、すべて架空のデータ（「サンプル」「利用者A」など）で統一する。

## 8. 確認したいこと（図にない・決まっていないこと）

1. **予約確定・決済完了後の遷移先および表示**:
   * 遷移図では予約・購入の最後が画面右側へ抜けており、具体的な画面遷移先が明記されていません。本仕様書では仮として「確定/決済完了のお知らせ表示後、ホーム画面 (`index.html`) へ戻る」挙動と設定しています。
2. **「登録（ログイン）」ボタンの遷移**:
   * 登録・ログイン選択画面 (`auth-choice.html`) で「ログイン」を押した場合の挙動が図に明示されていないため、仮で「マイページ (`mypage.html`)」に遷移する仕様としています。
3. **下部ナビゲーションの存在領域**:
   * ワイヤーフレーム上、マイページおよび一部画面のみ下部ナビ（ホーム / 予約 / カート / マイページ）が描画されています。アプリ全体で統一して下部ナビを表示するか、特定画面のみとするかの決定が必要です。
