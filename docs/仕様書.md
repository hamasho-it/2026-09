# アプリ仕様書：リハウス

## 1. アプリの名前と目的
- **アプリ名**: リハウス
- **目的**: 
  - **ターゲット**: 「同じ飲食店ばかりで飽きる」「長居しづらい」「外食費が高い」といった悩みを抱える学生や旅行客。
  - **解決策**: 地域課題である空き家を活用し、個室のフリースペースを時間制で提供することで、友達と気軽に長居できる環境を実現する。さらにシアタールーム等のセットプランを用意し、お得に利用できるようにする。

## 2. 画面一覧（画面名と表示内容）

| 画面名 | 表示内容 |

| ホーム画面 | 各機能への導線ボタン（「予約する」「購入する」「マイページ」「新規ログイン」）、店舗基本情報（営業時間・住所）、お得なお知らせバナーを表示 |

| 購入画面（決済・完了） | 注文内容一覧・お支払い金額の最終確認。「お支払いをする」を押すと「支払いを確定する」ボタンを表示し、確定押下後に注文確定メッセージと「戻る」ボタンを表示 |

## 7. 守る条件

1. **技術スタック制限**:
   * HTML5、CSS3、JavaScript (Vanilla JS) のみを使用する。
   * データベースおよびサーバーサイド処理（ログイン認証含む）は実装しない。
2. **ファイル構成**:
   * CSSは `./style.css` の1ファイルに集約し、全画面で共通読み込みを行う。
   * JavaScriptは `./script.js` の1ファイルに集約し、全画面で共通読み込みを行う。
   * リンク・リソースパスはすべて `./` から始める相対パスを使用する。
3. **デザイン・レスポンシブ**:
   * スマートフォン端末（375px〜430px程度の幅）での閲覧に最適化する。
   * カラーパレットは白・黒・灰色（モノトーン）を基本とする。
4. **表記・文字・機能制御**:
   * ワイヤーフレーム内のカッコ `（ ）` は仮の記号のため画面表示からは除外する。
   * 実在の人物・店舗・地名・連絡先は使用せず、架空のデータで統一する。
   * マイページ内は `＞` アイコンを外し、ユーザーネーム横に「設定」ボタン/リンクを配置する。
   * 通常プラン時は1〜5時間の選択肢を設け、セットプラン時は2時間固定の表示切替を行う。
   * 購入画面で「お支払いをする」押下後に「支払いを確定する」ボタンを表示し、確定時に「注文内容が確定しました」の文言と「戻る」ボタンを表示する。

## 8. 確認したいこと（図にない・決まっていないこと）

1. **予約確定後の遷移先**:
   * 予約確認画面で「この内容で予約する」を押した後は、仮として「予約完了のお知らせ表示後、ホーム画面 (`index.html`) へ戻る」設定としています。
2. **「ログイン」ボタンの遷移先**:
   * 登録・ログイン選択画面 (`auth-choice.html`) で「ログイン」を押した後は、仮で「マイページ (`mypage.html`)」へ遷移する仕様としています。
